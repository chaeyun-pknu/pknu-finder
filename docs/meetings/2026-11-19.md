## 3. 논의 내용과 결정 사항 (이유 포함)

- **채팅 자동 갱신 기능 구현에 따른 Supabase 인증 오류**
채팅 메시지 송수신 기능 개발 과정에서 `st.fragment()`를 활용한 3초 간격의 메시지 자동 갱신 기능을 구현함. 자동 갱신 시 `get_supabase_client()`가 반복 호출되면서 클라이언트 생성 및 인증 과정에서 `Request rate limit reached`, `The read operation timed out` 오류가 발생함.기존 DB 구조에서는 클라이언트 생성 및 사용자 인증 과정이 반복되어 불필요한 인증 요청이 발생하는 것으로 추정됨.해당 문제를 해결하기 위해 다음 두 가지 방안을 논의함.
    - **방안 1. DB 인증 구조 개선:** 기존 인증된 클라이언트를 재사용하여 반복 인증 요청을 줄이고, 3초 간격의 자동 갱신 기능을 유지하는 방법
    - **방안 2. 채팅 자동 갱신 방식 변경:** 주기적인 자동 갱신을 제거하고, 메시지 전송 후 갱신 및 수동 새로고침 방식으로 변경하여 요청 횟수를 줄이는 방법
    
    방안 1로 결정하여 자동 갱신 기능은 유지한채, 기존 클라이언트를 재사용하는 방식으로 수정함.
